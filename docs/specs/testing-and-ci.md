# Testing and CI

- Vitest with four projects. `core`: node, for the pure logic. `server`: `@cloudflare/vitest-plugin` runs the tests in `workerd` with a real local D1 (`env` from `cloudflare:workers`). `front`: jsdom and Testing Library, with `stubApi` and `renderApp` in `src/lib/test/render-app.tsx`; `renderApp` mounts the real `AppProviders` (language, theme, sign-in gate and per-user data) over memory storage and a fake sign-in (`createFakeAuth`: signed in as `TEST_USER` unless told otherwise), and tests read their expected copy from `en.json`; `renderAppHook` runs a hook under the same providers. The `server` and `front` projects allow a test 20 s, since the runners of CI are about ten times slower than a laptop; a test that needs hundreds of requests seeds its rows with SQL instead. `docs`: node, checks that the index of `AGENTS.md` lists every ADR and every spec, that each ADR is numbered and headed as its file name says, and the deploy configuration (`wrangler.jsonc`, the scripts of `package.json` and the icons of the prerelease).
- A request without a handler in a test fails; it never reaches the network.
- `design-system/` goes through `types:check` and `lint` (its CSS too) with the rest. Stories are not tests and there is no Storybook test addon ([ADR-0011](../adr/0011-design-system-in-storybook.md)); CI doesn't build Storybook, so a broken story never stops a release. What only a build catches, a path Vite can't resolve, shows when `pnpm storybook` starts.
- **CI and the hook**: a husky `pre-commit` runs `format:check`, `types:check`, `lint` and `test`. GitHub Actions (`.github/workflows/ci.yml`, one job, `check`) runs the same plus `build` on every push to `main` and on a pull request to `main`. It deploys nothing and holds no Cloudflare secret: Cloudflare Workers Builds builds and deploys every push ([repository structure](repository-structure.md), [ADR-0015](../adr/0015-cloudflare-deploys-and-a-prerelease-worker.md)), without running the tests, so a push whose checks fail is still deployed; the hook is what stops it first. A branch other than `main` runs no CI and goes to the prerelease.
- **The prerelease.** A test reads `wrangler.jsonc` and fails if `env.prerelease` binds the same D1 database as the top level, or lacks its own, since a deploy of that environment over a normal build would otherwise reach production data. It fails too when the scripts stop pairing `--env prerelease` with a prerelease build (`CLOUDFLARE_ENV=prerelease`), the migrations included, or when `public/prerelease/` stops holding the same icon files as `public/` (in another color).
- **Shared expenses.** The maths in `core/` (split, balances, simplify, the personal rows) is tested on its rules rather than on a few examples: shares always add up to the amount, the cents left of an equal split land on every member over many seeds, the balances of a group add up to zero, simplified payments settle every balance, and a settlement of more than the debt turns it round. `server` tests make several users with `signIn(email, name)` and check that nobody reads or writes a group they aren't in, that an invitation serves one person once (leaving no half-made friend when two accept at once), and that leaving or deleting with a balance is refused. `front` tests add groups to `createFakeApi` (with a cursor per group, refusals with a code, writes whose answer is lost, and `hold` to keep requests waiting) and cover writing offline, the order and the retries of the outbox of groups, leaving, two accounts on one device, and the form in both tails, with `randomSeed` (`src/lib/random-seed.ts`) mocked to choose who gets the cents left.
