# Frontend

- TanStack Router (file-based; `src/routeTree.gen.ts` is generated by the Vite plugin and committed) and TanStack Query. API client: `hc<AppType>('/')` in `src/lib/api`.
- Imports in `src/`: `./` inside the same folder, otherwise `@/` (and `@server/` for types only), never `../`.
- **i18n** with `use-intl`, as in `spa-hoardex`. Messages live in `src/assets/locales/{en,es}.json`, English is the default and the source of the key types. The locale comes from the stored preference, then `navigator.languages`, then English, and it is not part of the URL. A test checks that every locale has exactly the same keys. No UI copy is hard-coded in components.
- **Mobile-first**: base CSS targets phones and widens with `@media (width >= 40rem)` and `(width >= 64rem)`. Touch targets are at least `--size-touch` (44 px), layouts honor `env(safe-area-inset-*)` (`viewport-fit=cover`), full-height blocks use `dvh`, and form controls inherit 16 px so iOS doesn't zoom on focus.
- Styles: plain CSS with variables and native nesting, no SCSS and no Tailwind (reversible if needed). Variables in `src/assets/styles/tokens.css`, BEM in the CSS of each route or component, Stylelint with alphabetical properties and no `!important`. Transitions always use the `--duration-*` and `--ease-*` tokens; `prefers-reduced-motion` zeroes them in a single place.
- Visual rules (colors, themes, shape, motion) live in [`DESIGN.md`](../../design-system/DESIGN.md).
- Shared components live in `src/components/<name>/` with their CSS and tests next to them: `Brand` (the logo), `Notice` and `LiveNotice`, `Toast`, `Announcer`, `ScreenTitle`, `Button`, `Field`, `Select`, `DateRangeFields`, `Card` and `CardList`, `Sheet`, `Disclosure`, `Dialog` (also as a sheet), `ChoiceGroup`, `Icon`, and, with the shared expenses, `BottomNav` (with its "+" action) and `Checkbox`. Screens compose them instead of restyling raw elements (see [Components](../../design-system/DESIGN.md#components)).
- Shared components take their copy by props: they read no messages (`use-intl`), import no virtual module (`virtual:*`) and only the links (`ButtonLink`, `TabLink` and `BottomNav`) know the router. `Toast` reads the duration tokens through `lib/motion` and `DateRangeFields` the day check of `core/date`; both stay.
- **Screen titles, the focus and what is said when a screen opens** (WCAG 2.4.2, 2.4.3, 4.1.3). Every screen has one `h1`, a `ScreenTitle` (`src/components/screen-title`), never a bare `h1`, and the brand is not a heading. The title of the page is that heading's text followed by the app: "Groups – Tarja", a group's screen under its name, the settings of a group under their own heading, the home screen "Expenses – Tarja" and, while a pinned tab of it is shown, "<group name> – Tarja" (the heading under the tabs is the group's name, read by assistive technology only). `index.html` keeps the plain "Tarja" for the moment before the app starts. How a screen was reached decides what its heading does when it appears (`useScreenArrivals`, `src/lib`, which tells the heading through `src/lib/screen-arrival`):
    - **Any change of screen that is not made from the navigation that is always there** (a card of Settings or Groups, "Create the group", the link back of the header, Join, a button of a banner, a redirect after an action, a push notification that opens a screen) moves the focus to the `h1` of the new screen: the control that was pressed is gone or is no longer the place. The heading has `tabindex="-1"`, is not in the tab order, and draws no ring when a script gives it the focus (a heading is not a control). The focus moves without scrolling.
    - **The navigation that is always there** (the bottom bar, the header words and the logo, the tabs of Expenses; the controls inside a `nav` or marked `data-keeps-focus`) and **a swipe between screens** leave the focus where it is, and the new title is said instead through the polite status of the `Announcer` (`src/components/announcer`), hidden on screen and always in the page, whose text changes inside it. So does a step back or forward through the browser's history. A swiped screen opens while the finger is still down, so its title is said only once the finger lifts and the swipe goes on; a swipe that goes back says nothing at all, neither the screen it opened nor the one it returns to, since the person never left that one.
    - **Nothing happens when the app opens**, or when the address changes without changing the screen (the tab of Expenses shown last restoring itself, a group that is not pinned falling back to Expenses): the browser says the page by itself the first time.
    - A heading that appears later than `ARRIVAL_MS` (2 s) after the change, because its screen waited for data, is not an arrival and takes no focus. When something other than a change of screen needs the screen's heading (the list when a deleted row leaves no neighbour), `focusHeading` gives it the focus.
- **The `Announcer`** (`AnnouncerProvider`, `useAnnounce`) is the one way to say something to assistive technology that has no place on screen (the screen that opened, an expense added at home where no toast shows, [expenses](expenses.md)). A live region that arrives already filled is announced inconsistently, so the region is always there and only its text changes; a message said twice in a row is read twice (the text is emptied for a beat first); it says nothing outside its provider, as on the sign-in screen. Messages that come and go on a screen follow the same rule in their own region, which stays in the page (`LiveNotice` for a `Notice`; a `Notice` that is part of the screen from its first paint has no role). What changes with every key (the count of a search, what is left of an amount to split: `SpokenHint`) is shown at once but read out once the typing has paused for half a second (`useDebouncedValue`), from a visually hidden region, the visible copy being hidden from assistive technology so it isn't heard twice.
- **Landmarks**: a screen has `main`, the header and the navigation as its landmarks and nothing else. A `section` of a screen (the lists of Groups, the day groups of the expense list) is named by its heading inside it, never by `aria-labelledby` or `aria-label`, which would make it a region, one more stop for a screen reader on every list. A `nav` that holds a set of links (the pinned tabs) keeps its name.
- **Lists drawn with no marker** (`list-style: none`) lose their list semantics in Safari, so a `ul` or `ol` styled that way carries `role="list"` (the `CardList` does it for every card list, a description list needing none). The role looks redundant and is not: leave it.
- `src/lib` never imports from `src/features` (ESLint enforces it), so the composition of the app around its pages lives in `src/providers.tsx`, used by `main.tsx` and by the tests.
